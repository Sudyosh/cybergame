================================================================================
1. ภาพรวมของเกม
================================================================================

MUT Secure Vault เป็นเกม Capture The Flag (CTF) แบบเรื่องราว ออกแบบมาเพื่อ
การศึกษาความปลอดภัยไซเบอร์ ผู้เล่นจะได้เรียนรู้ผ่านการปฏิบัติจริงใน 3 ด่าน
ที่มีความยากเพิ่มขึ้นตามลำดับ

ประเภทเกม      : เกมการศึกษา (Educational CTF)
จำนวนด่าน      : 3 ด่าน
ธีม            : Terminal/Hacker (หน้าจอสไตล์เทอร์มินัล)
ภาษา           : รองรับภาษาไทยและภาษาอังกฤษ

เนื้อเรื่อง:
--------------------------------------------------------------------------------
คุณถูกเลือกให้เข้าถึงห้องนิรภัยดิจิทัลที่ซ่อนความลับสำคัญของมหาวิทยาลัย
ความลับนี้ถูกเข้ารหัสและป้องกันด้วยระบบรักษาความปลอดภัยหลายชั้น
ภารกิจของคุณคือการผ่านด่านทั้งสามเพื่อเปิดเผยความลับที่ซ่อนอยู่

================================================================================
2. ความต้องการของระบบและการติดตั้ง
================================================================================

ความต้องการของระบบ:
--------------------------------------------------------------------------------
- Node.js เวอร์ชัน 18 ขึ้นไป
- npm (Node Package Manager)
- Web Browser ที่รองรับ JavaScript สมัยใหม่
- พื้นที่เก็บข้อมูล 500 MB

การติดตั้ง:
--------------------------------------------------------------------------------
ขั้นตอนที่ 1: ติดตั้ง Backend (Server)

   เปิด Command Prompt หรือ Terminal แล้วพิมพ์:

   cd server
   npm install
   npm run dev

   Server จะทำงานที่ http://localhost:3001

ขั้นตอนที่ 2: ติดตั้ง Frontend (Client)

   เปิด Command Prompt หรือ Terminal อีกหน้าต่างแล้วพิมพ์:

   cd client
   npm install
   npm run dev

   Client จะทำงานที่ http://localhost:5173

4. ด่านที่ 1: การเข้ารหัส (Cryptography)
================================================================================

วัตถุประสงค์การเรียนรู้:
--------------------------------------------------------------------------------
   - เข้าใจการแลกเปลี่ยนกุญแจแบบ Diffie-Hellman
   - เรียนรู้การเข้ารหัสแบบสมมาตร AES-256
   - เข้าใจลายเซ็นดิจิทัล RSA
   - รู้จักฟังก์ชันแฮช SHA-256

เนื้อเรื่องด่าน:
--------------------------------------------------------------------------------
   ผู้ก่อตั้งได้ซ่อนความลับไว้ในปี 1990 โดยเข้ารหัสข้อความด้วยเทคนิค
   การเข้ารหัสหลายชั้น คุณต้องถอดรหัสข้อความนี้เพื่อค้นหา FLAG แรก

ขั้นตอนการเล่น:
--------------------------------------------------------------------------------
ขั้นตอน 1: ดาวน์โหลด Artifacts
   - คลิกปุ่ม "ดาวน์โหลด Artifacts"
   - ระบบจะให้ข้อมูลสำคัญ:
     * DH Parameters (พารามิเตอร์ Diffie-Hellman)
     * RSA Public Key (กุญแจสาธารณะ RSA)
     * AES IV (Initial Vector สำหรับ AES)

ขั้นตอน 2: แลกเปลี่ยนกุญแจ Diffie-Hellman
   - ใช้ DH Parameters ที่ได้รับ
   - สร้างคู่กุญแจส่วนตัวและกุญแจสาธารณะ
   - ส่งกุญแจสาธารณะของคุณไปยัง server
   - รับกุญแจสาธารณะของ server กลับมา
   - คำนวณ Shared Secret

ขั้นตอน 3: สร้าง AES Key
   - ใช้ Shared Secret ที่คำนวณได้
   - รวมกับ salt "suranaree"
   - สร้าง AES-256 Key

ขั้นตอน 4: ถอดรหัสข้อความ
   - ดึงข้อความเข้ารหัสจาก server
   - ใช้ AES-256-CBC ถอดรหัส
   - อ่านข้อความที่ซ่อนอยู่

ขั้นตอน 5: ตรวจสอบลายเซ็น RSA
   - ดึงลายเซ็นดิจิทัลจาก server
   - ใช้ RSA Public Key ตรวจสอบความถูกต้อง
   - ยืนยันว่าข้อความไม่ถูกแก้ไข

ขั้นตอน 6: สร้างและส่ง FLAG
   - รวมข้อมูล: ข้อความ + วันที่ + ลายเซ็น
   - คำนวณ SHA-256 hash
   - FLAG รูปแบบ: MUT{32-character-hex}
   - ส่ง FLAG เพื่อผ่านด่าน

คำใบ้:
--------------------------------------------------------------------------------
   - สังเกตปริศนา Fragment ที่ซ่อนในข้อมูล
   - วันที่สำคัญ: 27/07/2533 (พ.ศ.)
   - Caesar Cipher มี shift = 17

5. ด่านที่ 2: การยืนยันตัวตน (Authentication)
================================================================================

วัตถุประสงค์การเรียนรู้:
--------------------------------------------------------------------------------
   - เข้าใจหลักการ Multi-Factor Authentication (MFA)
   - รู้จัก 3 ปัจจัยในการยืนยันตัวตน
   - เรียนรู้ระบบ OTP (One-Time Password)

เนื้อเรื่องด่าน:
--------------------------------------------------------------------------------
   ผู้พิทักษ์ได้กำหนดการพิสูจน์ตัวตน 3 อย่างเพื่อยืนยันว่าคุณเป็นผู้มีสิทธิ์
   เข้าถึงห้องนิรภัย คุณต้องผ่านทั้ง 3 ปัจจัยเพื่อได้รับ FLAG ที่สอง

3 ปัจจัยยืนยันตัวตน:
--------------------------------------------------------------------------------
ปัจจัย 1: Email OTP (สิ่งที่คุณได้รับ)
   - ระบบจะส่งรหัส OTP 6 หลักไปยังอีเมลของคุณ
   - รหัสมีอายุ 5 นาที
   - สังเกต Header ที่ซ่อนอยู่: X-Vault-Fragment

ปัจจัย 2: Password (สิ่งที่คุณรู้)
   - รหัสผ่านจะมีคำใบ้ในอีเมล (เป็นตัวอักษรที่สลับที่กัน)
   - ต้องเรียงตัวอักษรให้ถูกต้อง
   - รหัสผ่าน: computer_engineering_#28!

ปัจจัย 3: PIN (สิ่งที่เฉพาะตัว)
   - รหัส PIN 5 หลัก
   - คำใบ้จากซองจดหมาย: รหัสไปรษณีย์ มทส.
   - คำตอบ: 30000
   - มีโอกาสลองผิดได้ 3 ครั้ง
   - หากผิด 3 ครั้งจะถูกล็อค 15 นาที

ขั้นตอนการเล่น:
--------------------------------------------------------------------------------
ขั้นตอน 1: ส่ง OTP
   - คลิก "ส่ง OTP"
   - ตรวจสอบอีเมลของคุณ
   - กรอกรหัส OTP 6 หลัก

ขั้นตอน 2: ตรวจสอบ OTP
   - กรอกรหัส OTP ที่ได้รับ
   - คลิก "ตรวจสอบ"

ขั้นตอน 3: กรอกรหัสผ่าน
   - ใช้คำใบ้จากอีเมลเพื่อไขรหัสผ่าน
   - กรอกรหัสผ่านที่ถอดรหัสได้

ขั้นตอน 4: กรอก PIN
   - ใช้คำใบ้เรื่องซองจดหมาย
   - กรอกรหัส PIN 5 หลัก

ขั้นตอน 5: ส่ง FLAG
   - เมื่อผ่านทั้ง 3 ปัจจัยแล้ว
   - ระบบจะสร้าง FLAG ให้
   - ส่ง FLAG เพื่อผ่านด่าน

6. ด่านที่ 3: การควบคุมสิทธิ์ (Authorization)
================================================================================

วัตถุประสงค์การเรียนรู้:
--------------------------------------------------------------------------------
   - เข้าใจ Role-Based Access Control (RBAC)
   - เรียนรู้ Access Control Matrix (ACM)
   - รู้จัก Bell-LaPadula Model (MLS)
   - ค้นพบและใช้ช่องโหว่ในระบบควบคุมสิทธิ์

เนื้อเรื่องด่าน:
--------------------------------------------------------------------------------
   ห้องนิรภัยมีระบบลำดับชั้นความลับหลายระดับ คุณเริ่มต้นเป็น Student
   ที่มีสิทธิ์เข้าถึงต่ำที่สุด ต้องหาช่องโหว่ในระบบเพื่อยกระดับสิทธิ์
   และเข้าถึงไฟล์ FINAL_FLAG ที่เป็นความลับสูงสุด

ระดับความลับ (Security Levels):
--------------------------------------------------------------------------------
   ระดับ 1: PUBLIC        - สาธารณะ
   ระดับ 2: CONFIDENTIAL  - ลับ
   ระดับ 3: SECRET        - ลับมาก
   ระดับ 4: TOP_SECRET    - ลับที่สุด

ลำดับชั้นบทบาท (Role Hierarchy):
--------------------------------------------------------------------------------
   Student    (ระดับ 1) - บทบาทเริ่มต้น
   Researcher (ระดับ 2) - นักวิจัย
   Admin      (ระดับ 3) - ผู้ดูแลระบบ
   Director   (ระดับ 4) - ผู้อำนวยการ

ขั้นตอนการเล่น:
--------------------------------------------------------------------------------
ขั้นตอน 1: ตรวจสอบบทบาทปัจจุบัน
   - คลิก "Who Am I" หรือ "ฉันคือใคร"
   - จะเห็นว่าคุณเป็น Student (ระดับ 1)

ขั้นตอน 2: สำรวจระบบ
   - ดู Access Control Matrix
   - ดูกฎการเข้าถึงต่างๆ
   - ดูทรัพยากรที่มีอยู่

ขั้นตอน 3: ใช้ช่องโหว่ที่ 1 - Delegation Flaw
   - ส่งคำขอเข้าถึงทรัพยากร (Request Access)
   - ช่องโหว่: ระบบจะเลื่อนบทบาทแทนที่จะแค่ให้สิทธิ์ชั่วคราว
   - คุณจะได้เลื่อนจาก Student เป็น Researcher

ขั้นตอน 4: ใช้ช่องโหว่ที่ 2 - Declassification Bug
   - ช่องโหว่: ระบบเชื่อ requester_role จาก body โดยไม่ตรวจสอบ
   - ใช้ Declassify โดยอ้างว่าเป็น Director
   - ระบบจะให้เข้าถึงไฟล์ลับที่สุด

ขั้นตอน 5: เข้าถึง Final Flag
   - หลังจาก Declassify แล้ว
   - ดึงไฟล์ FINAL_FLAG
   - ส่ง FLAG เพื่อจบเกม

ทางเลือก: ช่องโหว่ที่ 3 - Time Header Bypass
   - ระบบมี Maintenance Window เวลา 02:00-03:00
   - ช่องโหว่: สามารถส่ง Header X-System-Time: "02:30"
   - ระบบจะ bypass การตรวจสอบความปลอดภัย
   - เข้าถึงทรัพยากรได้โดยตรงผ่าน GET /api/c3/resources/{id}

วิธีใช้ช่องโหว่ (Technical Details):
--------------------------------------------------------------------------------
ช่องโหว่ที่ 1: Delegation Flaw

   ส่ง POST request ไปที่ /api/c3/request-access
   Body: { "resource": "any", "reason": "any" }

   ผลลัพธ์: บทบาทจะเลื่อนจาก Student เป็น Researcher

ช่องโหว่ที่ 2: Declassification Bug

   ส่ง POST request ไปที่ /api/c3/declassify
   Body: {
     "resource": "FINAL_FLAG.txt",
     "requester_role": "Director",
     "reason": "any"
   }

   ผลลัพธ์: ได้เนื้อหาไฟล์ FINAL_FLAG โดยตรง

ช่องโหว่ที่ 3: Time Header Bypass (ทางเลือก)

   ส่ง GET request ไปที่ /api/c3/resources/4
   Headers: X-System-Time: "02:30"

   ผลลัพธ์: เข้าถึงไฟล์ Top Secret ได้โดยตรง

7. เคล็ดลับและคำแนะนำ
================================================================================

เคล็ดลับทั่วไป:
--------------------------------------------------------------------------------
   1. อ่านเนื้อเรื่องและคำใบ้อย่างละเอียด
   2. สังเกต HTTP Headers ที่ซ่อนอยู่
   3. ใช้ Developer Tools ของเบราว์เซอร์ (F12)
   4. บันทึกข้อมูลสำคัญไว้ระหว่างเล่น
   5. ถ้าติดขัดให้ลองวิธีใหม่

เคล็ดลับด่านที่ 1:
--------------------------------------------------------------------------------
   - ใช้เครื่องคิดเลข Crypto ที่มีให้ในเกม
   - salt สำหรับ AES คือ "suranaree"
   - วันที่เป็นพุทธศักราช (2533 = 1990)

เคล็ดลับด่านที่ 2:
--------------------------------------------------------------------------------
   - ตรวจสอบอีเมลทั้งเนื้อหาและ Headers
   - รหัสไปรษณีย์ มทส. = 30000
   - อย่าลองผิดเกิน 3 ครั้ง

เคล็ดลับด่านที่ 3:
--------------------------------------------------------------------------------
   - ศึกษา API endpoints ที่มีให้
   - สังเกตกฎเรื่อง Maintenance Window
   - ลองส่ง Custom Headers
